# Performance plan after 0.31

Status: proposed implementation work. The 0.31 runtime is published in PR #42;
this plan does not implement the next tranche.

## Decision and evidence

Prioritize **compiled calls and virtual-frame execution for 0.32**. Those costs
remain substantial in recursive Fibonacci, binary trees, and spectral norm.
The 0.31 branch-loop and invariant-field improvements already moved their
target workloads almost entirely into generated Python, so more work on their
outer VM dispatch is unlikely to help much.

Fresh profiles of runtime revision `b7a655d` are recorded in
[`profile_031.json`](../benchmarks/results/profile_031.json), using CPython
3.14.7, five warmups, and one profiled execution per workload. Every execution
checks its expected result. These are **instrumented self-time shares**, useful
for selecting work; they are not normal elapsed times or predicted speedups.
The unprofiled 0.31 A/B baseline remains in
[`speed-0.31.md`](speed-0.31.md).

| Workload | Observed remaining work | Consequence |
| --- | --- | --- |
| Recursive Fibonacci | 21,888 child-call wrapper entries; 21,890 frame acquisitions/releases. Wrapper + acquire + release account for about 49% of self time. | Optimize the compiled-call entry path before attempting a larger recursion rewrite. |
| Spectral norm | 18,000 virtual entries and 18,000 child-call wrappers; together about 46% of self time. | Cache the final execution entry and inline eligible tiny numerical callees. |
| Binary trees | 30,600 child-call wrappers, 30,637 GC adoption calls, and 30,660 table writes. | Call work should help first; allocation and adoption need a separate measured pass. |
| Sieve | About 26% of self time in the interpreter loop, 92,559 `Frame.proto` property calls, 5,001 CFG branch checks. | Expand useful compiled coverage; avoid treating property access alone as the whole problem. |
| Table mix | About 74% inside the generated region; 24,000 generic type checks and over 54,000 `isinstance` calls. | Inspect the generated bytecode and remove only guards proven redundant by IR. |
| 1,000 Python calls | `LuaRuntime.call` and direct leaf entry together account for about 51% of self time. | A reusable bound call adapter remains a later opportunity. |

## 0.32: five ordered changes

Implement each as a separate reviewable commit. Capture the baseline first and
re-profile after steps 1–3 before committing to the higher-risk steps 4–5.

### 1. Cache the final compiled execution entry

The current call-site cache saves Closure/compiled-function pairs, but
`run_compiled_child` still checks a second virtual-frame cache and repeatedly
looks up frame acquisition/release methods.

- Resolve a per-Proto execution descriptor once: virtual runner or ordinary
  compiled runner, including a cached refusal to virtualize.
- Let the existing call-site identity guard select that descriptor directly.
  Keep the current Closure as a runtime argument so environments and captured
  values are never frozen into the descriptor.
- Keep stack-depth, hook/re-entry, JIT-disable, and fallback checks at the
  boundaries where their values can change. Preserve the generic VM path for
  unsupported callers.
- Primary files: `function_jit.py`, `optimizing_jitvm.py`, `virtual_frame.py`.
- Evidence of success: fewer wrapper/cache/method-lookup operations in warmed
  Fibonacci and spectral norm, followed by an unprofiled timing improvement.

### 2. Generate fixed-arity argument and result adapters

- Specialize parameter binding for known arity and primitive annotations;
  replace repeated Python loops and generic `type_matches` calls with generated
  direct checks where appropriate.
- Use an unchecked internal entry only when current-path IR proves each actual
  argument matches the parameter. A typed source cookie or profiled value is
  insufficient. Python, dynamic, table-derived, and uncertain inputs retain
  their checks.
- Specialize the common one-result path without repeated length tests. Preserve
  zero results, multiple results, nil padding, ignored extras, and missing-arg
  errors in the general adapter.
- Primary files: `function_jit.py`, `virtual_frame.py`, `optimizing_jitvm.py`,
  and the existing CALL IR modules.
- Gate: exact invalid-argument/error ordering and fuel behavior for missing,
  extra, boolean, changing table-derived, and out-of-range integer inputs.

### 3. Reduce bookkeeping in pure virtual/basic blocks

- Bring the 0.31 path/block fuel-accounting approach to eligible virtual-frame
  and whole-function blocks. Their emitters still increment `used` and update
  diagnostic PC state for individual instructions.
- Batch only operations whose error/side-effect behavior is known. Record exact
  prefixes before calls, guards, runtime errors, or suspension; reconstruct the
  exact PC and registers when a partial budget cannot execute a block.
- Reuse the existing primitive-guard AST transformation rather than maintaining
  another set of integer/boolean/string checking rules.
- Primary files: `virtual_frame.py`, `function_jit.py`, `ast_backend.py`.
- Gate: every small fuel boundary, nested suspension, divide/modulo errors,
  traceback lines, and Lua integer/float loop boundaries match the interpreter.

### 4. Spill only state that must survive a compiled call

Whole-function compilation currently spills every allocated register before
each compiled child call, including dead temporaries.

- Use existing CFG liveness and escape facts to define the required spill set:
  continuation-live values, open/captured cells, GC roots, and diagnostic or
  unwind state that can become visible at that boundary.
- Start with pure, non-capturing callers; retain full spills whenever the
  analysis cannot prove a smaller safe set.
- Check inactive frame-pool retention as well as speed. Fewer writes must not
  leave stale objects retained indefinitely or hide live objects from Lua GC.
- Primary files: `function_jit.py`, CFG/value IR, `escape_analysis.py`;
  review the root expectations in `gc.py` and `vm.py`.
- Gate: nested deoptimization, child errors, GC during callbacks, captured
  locals, and repeated calls with large temporary tables remain correct.

### 5. Inline small pure callees inside compiled numerical functions

- Extend existing CALL/value-IR inlining into selected whole-function numeric
  loop shapes. Spectral norm is the first concrete target: its tiny numerical
  helper currently enters a virtual runner 18,000 times.
- Require fixed arity, bounded emitted size, no observable closure/frame
  identity, and complete side-effect/type facts. Reuse existing analyses.
- Preserve the logical Lua call's fuel and stack-depth semantics even when its
  Python call disappears. Keep mutation, hooks, unsupported captures, and
  dynamic targets on their existing paths.
- Primary files: `call_ir.py`, `value_ir_function_jit.py`,
  `direct_call_ir_function_jit.py`, `function_jit.py`.
- Gate: callee changes, closure environments, argument/result counts, code-size
  growth, compile time, and stack/fuel limits. Do not unroll general recursion.

## Following work, conditional on fresh profiles

| Priority | Work | First target and boundary |
| --- | --- | --- |
| Next | Broader structured control flow | Bring proved numeric `for`/`while`, multiple diamonds, and selected nested loops into whole-function compilation. Start with sieve and table mix; preserve side exits and accept only reducible shapes. Reuse shared loop/fuel semantics. |
| Next | Allocation and table writes | Optimize adoption of freshly allocated, already-owned objects and eligible table-constructor batches; consider caching the GC threshold with exact invalidation. Preserve debt accounting, old-to-young barriers, weak tables, finalizers, and `collectgarbage` controls. Target binary trees and table mix. |
| Later | Bound Python call adapters | Reuse a closure/arity/conversion descriptor across `LuaFunction` calls. Use bounded, runtime-owned caches and refresh dynamic controls on every call. Benchmark scalars, unions, containers, callbacks, and re-entry. |
| Later | Coroutine and string paths | Investigate resume/yield host transitions and guard/conversion repetition only if those workloads matter in the broader corpus. String builder transformations require proof that intermediate strings and allocation/fuel behavior are unobservable. |
| Research | Compact recursive activation stack | Consider virtualizing recursive activations only if the cheaper call work leaves a large residual. This requires exact frame reconstruction, logical Lua depth, unwind, hooks, and GC roots; a Python-recursive shortcut alone is insufficient. |

A supporting cleanup should consolidate constant-key classification and
primitive guard rules across PIC, dense, structured, typed-IR, and function
emitters. The integral-float key fixes show why these rules need one semantic
source and cross-tier regression cases. Keep that extraction behavior-neutral
and separate from widening any fast path.

## Measurement and acceptance gates

1. Record cold, warm, and steady execution separately on both CPython 3.13 and
   3.14. Add compilation time, generated code size, frame allocation counts,
   materialization counts, and retained memory for the changed path.
2. Use unprofiled same-machine runs against the published 0.31 source. Keep CPU
   affinity/hash seed consistent, alternate order, and use at least three paired
   processes with 7 warmups and 31 samples for the affected kernels. Keep the
   0.31 branch/table/Python-entry benchmarks as regression controls.
3. A suggested retention threshold is a repeatable >=5% improvement on a named
   affected workload, beyond paired-run variation, with no unexplained >5%
   regression on the other supported Python version or an important control.
   Treat this as an engineering decision gate, not a promised gain. Reject
   changes that only improve instrumented profile time.
4. Run the Python suite on 3.13/3.14, all 24 required official Lua 5.5.1 probes,
   and the pinned Penlight/luatest/LuaCov/AWfY checks. Add focused differential
   cases for the optimization's actual guards and side exits. Preserve the
   already documented unsupported host/native boundaries.
5. Keep ordinary Lua's wrapping integers and metamethod semantics intact.
   Explicit `integer`/`LuaInt` remains the no-overflow contract. Keep the
   implementation Python-only and retain the sandbox and opt-in hook behavior.
6. Before merging each implementation tranche, require green CI on its final
   head, publish the complete A/B table including unchanged/slower controls,
   and document the admitted shapes and fallback behavior.

Reproduce the diagnostic profile after installing the project:

```bash
PYTHONPATH=src python benchmarks/profile_hotpaths.py \
  --revision b7a655d --json /tmp/profile031.json
```

Use `--workload fib_recursive --workload spectral_norm` to focus that tool.
Use `benchmarks/compare_runtimes.py` for the broader four-runtime corpus, and
`benchmarks/speed_031_ab.py` for the established 0.31 controls. Profiles guide
which code to inspect; those unprofiled benchmarks decide whether to keep it.
